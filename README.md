# Enterprise AI Advisory System
### Oracle Fusion Cloud HCM + ERP | SLED Solution Advisor

**Daily-use Oracle enterprise solution advisory tool | Human-directed, source-grounded AI**

> **What it does:** I use this Oracle Fusion Cloud HCM and ERP Advisor throughout my workday to research product capabilities, assess configuration options, plan implementations, troubleshoot problems, build demonstrations, evaluate integrations, and answer RFP and cross-module solution questions for state and local government and education (SLED). It covers the full HCM suite and connected ERP/Financials processes, not only Time and Labor or Payroll.

**Why I built it:** I needed a practical, repeatable way to work through complex Oracle questions across modules while refusing unsupported feature claims and preserving my authority over recommendations, commitments, and decisions. My real work often involves confidential customer information that cannot be published. The fictional CPUS case provides a safe, inspectable demonstration of the kind of reasoning the Advisor supports. It does not represent the scope or frequency of my actual use.

**Under the hood:** An instruction-driven ChatGPT Project, five original governing sources, Oracle product and release scoping, source-by-source evidence checks, implementation and configuration decision workflows, cross-module dependency analysis, six-category fit/gap classification, and human-led adversarial review. This is not a Python program, a trained model, a deployed Oracle integration, or an autonomous agent.

**Source requirement:** **No Oracle-specific capability, configuration, implementation, integration, licensing, security, or solution recommendation is to be offered without a relevant, real, traceable Oracle source citation.** Cite the Oracle document or Help Center resource that supports the specific claim, check release and country applicability, and separately flag tenant/contract/policy uncertainty. If such evidence cannot be found, **do not issue the recommendation as established Oracle functionality**. Provide a research or validation path instead. For law and labor obligations, use applicable official legal/policy sources as well; Oracle product documentation alone cannot prove compliance.

**Red-team ownership:** **I personally conduct the red-team challenge and decide whether advice is acceptable.** The ten AI-simulated review roles in the included CPUS example are a supplemental demonstration only. They are not my personal red-team record, an independent human panel, or proof that an acceptance suite passed.

**Verification status:** **Active in daily professional advisory use, not independently certified or tenant-validated by this GitHub portfolio.** The portfolio's archive and source preservation have been checked locally. The original 30 behavioral tests, 8 metamorphic variants and 12 CPUS probes are designed but not independently executed. Daily consultation must not be confused with authorization to modify Oracle, process payroll, post finance entries, or guarantee client outcomes.

**Baseline transparency:** The five archived v1.0 sources remain untouched. They require official Oracle evidence for consequential claims, with some wording saying citations are required *when possible*. The stricter citation-before-recommendation rule and my personal red-team ownership are my stated current operating expectations, documented in [daily-use and evidence standard](docs/DAILY_USE_AND_EVIDENCE_STANDARD.md). This publication is **not** evidence that the strict rule has passed independent behavioral testing or has been installed as revised Project Instructions.

## Configuration and implementation support

I use the Advisor to translate requirements into practical implementation work: identify the owning modules; distinguish a delivered capability from a configuration option or integration; map prerequisites and dependencies; evaluate setup sequences, approval rules and security; develop workshop questions and fit/gap decisions; plan demonstrations, test cases, conversions and cutover checks; and troubleshoot unexpected outcomes across HCM and ERP.

For example, a late time-card issue is not automatically a Payroll defect. The Advisor can help identify the relevant Time and Labor validation or approval configuration, downstream transfer, Payroll consumption, costing and reporting touchpoints. It should provide **documented Oracle references**, what must be verified in the organization's release and tenant, expected evidence, and failure cases. It must not fabricate navigation paths, Fast Formula behavior, API endpoints, or implementation guarantees.

The Advisor provides **configuration and implementation guidance**, not direct access to a tenant. I remain responsible for reviewing sources, challenging the answer, choosing the design and authorizing real changes.

## Evidence before recommendations

My expected process is: scope the question by module, release, country and business context; locate official Oracle guidance for each material Oracle recommendation; cite the relevant real document/section and explain the supported mechanism; disclose customer-specific prerequisites and uncertainty; then put the advice through my own red-team scrutiny. If an applicable Oracle source cannot be verified, the answer should say **not verified** and identify exactly what needs checking, rather than give an unsupported confident recommendation.

An official Oracle citation proves only what that document says. It does not establish a customer's subscription, setup, licensing, privileges, policy, test outcome or legal compliance. Legal obligations require authoritative government and governing agreement/policy sources in addition to Oracle product documentation. See the [source-evidence ledger](verification/EVIDENCE_AND_CITATIONS.md) and [daily-use standard](docs/DAILY_USE_AND_EVIDENCE_STANDARD.md).

## Synthetic demonstration, not a real client engagement

**Cascadia Public University System (CPUS) is fictional.** The scenario involves Oregon and Washington campuses, a separately governed Ontario research affiliate, nonexempt/union/faculty populations, two concurrent assignments at different pay rates, project/grant funding and a shift crossing the November 1, 2026 Pacific daylight-saving fallback. It also includes an approved absence, after-approval corrections, effective-dated pay changes and payroll costs that must reconcile to finance/GL.

The client deliberately presents six flawed requests, including that an **OTBI report automatically blocks** payroll errors, every interfund journal is automatically posted by HCM+ERP, U.S. tax setup applies to Canada, any HCM customer owns Studio/Claw features, an agent can autonomously change deductions and post journals without policy, and every RFP requirement can be guaranteed native within 90 days.

For this synthetic test, the Advisor must answer the useful solution question **without inventing overtime amounts, licenses, mapping, law, integrations or commitments**. See [complete synthetic client requirements](case-study/CLIENT_REQUIREMENTS.md).

```text
User / decision maker
       |
       v
ChatGPT Project short governing instructions
       |
       +--> 01 Operating Standard (module, source, work modes, authority)
       +--> 02 Test & Acceptance (test design, NOT product facts)
       +--> 03 Deployment/Maintenance (setup, change control)
       +--> 04 ABVOS Auditor Report (same-context design self-audit)
       |
       v
Scope: module, release, country, customer proof, policy, license
       |
       v
Real Oracle citation for Oracle-specific recommendations; otherwise hold claim
       |
       v
Hard gates: product truth, country, authority, privacy, financial controls
       |
       +--> Supported insight + proof plan --> Human decision
       |
       +--> Unsafe / unknown claim held --> Safer alternative + next proof
```

**Functional flow for the CPUS case (logical, not tenant-verified):** HR/assignment eligibility → Time and Labor entry and calculations → approval/consumer validation → Payroll elements and retro → payroll costing → Subledger Accounting → GL; conditional Project Costing path reconciled separately to protect against grant double counting. A dashboard/report may identify a defect but cannot be equated with the control that prevents submission/transfer.

## Why this architecture

- **Control first:** deterministic business rules, approvals, reporting and reconciliation are safer than an unsupervised agent for policy-driven payroll/finance changes. Reporting and prevention have different authority and guarantees.
- **Evidence over confidence:** a current official product guide supports only its actual general claim; an applicable statute supports legal interpretation within its scope; customer-specific entitlement, policy and tenant execution need their own proof.
- **Failure is explicit:** unknown is not “native Yes” and not automatically “unsupported.” Hold the unsafe representation and provide an actionable proof path.
- **Human-directed:** I set objectives, operating rules, review requirements, and authorization boundaries, and I personally handle red-team challenges in my professional use. AI assisted with the demonstration analysis, simulated expert lenses, and collateral. Those simulated roles do not substitute for my own red-team review or independent acceptance.

## Try it yourself | in a staged ChatGPT Project

This is not a CLI. A reviewer needs a ChatGPT account with **Projects** access and the ability to use the provided baseline files. No Oracle tenant is needed to inspect the synthetic demo; verified real product claims/behavior would require authorized product/tenant access.

1. Create a **new test/staging ChatGPT Project**, named for the Advisor. Read [the original deployment guide](docs/03_DEPLOYMENT_AND_MAINTENANCE.md).
2. Open [`PROJECT_INSTRUCTIONS.txt`](PROJECT_INSTRUCTIONS.txt) and **paste its exact full contents into the Project Instructions** field. Do not replace it with this README or the longer operating file.
3. Upload the four knowledge documents unchanged: [`01_OPERATING_STANDARD.md`](docs/01_OPERATING_STANDARD.md), [`02_TEST_AND_ACCEPTANCE.md`](docs/02_TEST_AND_ACCEPTANCE.md), [`03_DEPLOYMENT_AND_MAINTENANCE.md`](docs/03_DEPLOYMENT_AND_MAINTENANCE.md) and [`04_ABVOS_AUDITOR_REPORT.md`](docs/04_ABVOS_AUDITOR_REPORT.md).
4. Check source access in a fresh chat by asking for the exact `H1-H8` descriptions and the six RFP categories. Compare to originals; record model and file version; this is a **smoke check**, not the acceptance suite.
5. Ask a sanitized synthetic case: *“A fictional public university uses Oracle Time and Labor and Payroll. An OTBI report shows late time cards. Does that report itself prevent unapproved time from reaching payroll? Explain what I would validate.”* Confirm that the response separates detection, configured validations/approvals and tenant proof.
6. Run each original [`T01-T30 and M01-M08`](verification/ACCEPTANCE_RESULTS.md) **in fresh chats per source procedure**, and independently score results including hard gates, with saved complete transcripts. Run the [12 CPUS probes](verification/ADVERSARIAL_TESTS.md) separately; do **not** claim they passed just because the answer key is present here.
7. For consequential Oracle facts, verify official documentation against release, country and tenant; seek qualified finance/payroll/legal and security review. Human owner authorizes any actual customer use.

If a policy/requirement change is proposed, keep the original version and add an approved versioned successor. **This ZIP does not edit your existing Advisor Project settings.**
