## 5. Contradictions and omissions explicitly checked

- **Official Oracle vs customer reality:** user-supplied tenant observations can establish customer facts but cannot redefine general Oracle product behavior; missing tenant fact remains conditional.
- **Missing evidence vs “Not Supported”:** an unknown result is not a fabricated negative or positive; use Requires validation unless definite evidence supports scoped non-support.
- **No assumed product enablement:** release, Redwood, country, feature/AI availability and licensing are distinct gates.
- **Agent vs deterministic alternatives:** evaluate prevention/reporting/standard workflows first; a proposed Claw design never grants execution permission.
- **Project memory vs customer confidentiality:** Project-only memory limits context outside the Project, but does not isolate customers in different chats within the same Project. Operator must segregate confidential customers.
- **In-depth support vs usability:** normal Q&A should be short; only complex/high-impact matters trigger detailed review.
- **No missing Codex documents:** intentionally excluded; instruction-driven product has no software dependencies, compiler, API server or software deployment contract.

## 6. Remaining limitations and conditions to proceed

**L1. Fresh ChatGPT Project test not performed.** Run smoke test, all P0, selected P1 and novel variants. Record actual outputs and failures, and use human/domain review; a prompt's formal presence is not proof of correctness.

**L2. No Oracle tenant or customer license inventory provided.** The package cannot prove product enablement, customer configuration, correctness of an arbitrary proposed Fast Formula, security assignment, agent entitlement or live payroll/GL behavior.

**L3. External source updates are time-dependent.** Product announcements and guides checked at build may become stale; answers must recheck consequential specifics for relevant release/country/date.

**L4. Same-context audit.** This report is not an independently isolated semantic test. Seek fresh-model or human independent review before relying on high-stakes or externally binding recommendations.

**L5. Instruction system cannot mechanically stop every model error.** The owner must review critical procurement, financial, legal, security and production recommendations; high-risk actions stay behind system-side authorization, product controls and approval.

**Proceed with installation and controlled pilot** using `03_DEPLOYMENT_AND_MAINTENANCE.md`. **Do not declare production behavioral acceptance** until the recorded external gates pass.

## 7. Preserved good controls and future regression checks

Preserve the self-sufficient short Project Instructions, official-source primacy, explicit six-way RFP categories, distinct Oracle AI taxonomy, customer-scoped provenance, approval-boundary discipline and useful conditional answers. Regression families: fake feature, secondary source promotion, US/Canada mix-up, reporting mistaken for blocking, grant-costing automatic assumption, AI full-auto assumption, file injection, execution without permissions, false tenant access and cross-customer bleed. If such failures recur in novel language, revise the governing abstraction rather than adding one-off Oracle feature exceptions.
