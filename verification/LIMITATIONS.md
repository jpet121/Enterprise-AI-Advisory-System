# Limitations, assumptions and what this demonstration does not prove

1. **Fictional published example, real private use:** The owner reports using the Advisor daily for real professional Oracle HCM and ERP advisory work, including configuration and implementation planning. Customer information cannot be disclosed. CPUS, employees, grants, time records and diagrams are synthetic. No Oracle tenant, user entitlement, contractual rights, grants ledger, production employer records, payroll register, collective agreements, live journal or privileged role was provided or accessed.
2. **Capability versus customer readiness:** Oracle documentation establishes general patterns but no CPUS capability or completeness. Generic Oracle Time and Labor/Payroll pages cannot be promoted to tenant-specific 26D proof. Oracle AI Agent Studio 26D docs establish prerequisites, not a customer license. Fusion Claw announcement does not establish tenant rollout/authority.
3. **No payroll/legal outcome:** Worker time, overtime hours, regular rate, DST adjustment, meal compensability, leave eligibility, public-sector exemptions, grant costs, withholding, interfund entries and closed-period treatment cannot be conclusively computed without business records, law and policy.
4. **Ontario separate:** U.S. W-2 and tax/deduction setup cannot be treated as Canadian T4/ROE processing; Canadian-specific Oracle localization has not been independently validated in a tenant.
5. **Red-team ownership vs AI role critique:** The owner personally handles red-team challenges during professional use. Ten review roles in this CPUS portfolio are one assistant's *same-context simulated perspectives*, not the owner's review record. Human SME, blind external review and fresh-context test runs are not established by this package.
6. **Behavioral suite unrun:** The package preserves 30 original test prompts, 8 metamorphic tests, 8 hard gates and 12 new CPUS probes. Their **design and mapping** are real; independent execution/acceptance is not.
7. **Static document integrity is not functional proof:** ZIP extraction, file hashes, original byte preservation and relative-link checks establish artifacts' integrity; not instruction effectiveness, factual correctness or safe Oracle transactions.
8. **No runnable app:** This is an instruction-driven ChatGPT Project plus textual design/evidence. It is not Python, a custom-trained AI model, a RAG server, deployed integration, Oracle Agent Studio agent or custom Fusion Claw runtime.
9. **No enterprise security certification:** Proposed safeguards - prompt-injection resistance, SoD, PII controls, data retention and read-only agent - need authorized testing. No record-level security test or penetration test occurred.
10. **No measured implementation outcomes:** No cost savings, answer accuracy rate, time-to-revenue, go-live duration, throughput, response latency, financial reconciliation result or customer production acceptance was measured or claimed.
11. **Current and jurisdiction applicability can change:** Oracle pages, law and tax guidance require recertification against the release, location, employer and as-of date at implementation.
12. **Strict citation standard not retroactively proven:** Owner-directed current practice demands a relevant official Oracle citation before every Oracle-specific recommendation, but the exact preserved v1.0 files specify source citations for consequential claims "when possible." The stricter rule is documented separately, not installed or independently acceptance-tested by this ZIP.
13. **Publishing limitation:** This portfolio can show disciplined design and an honest synthetic demonstration. It cannot support claims that the advisor is certified, deployed, tenant-validated, production-ready or legally compliant for CPUS.
